# Size and speed

The shell is a thin runtime over the system webview, so what ships is mostly wry,
tao and the Rust standard library. That floor is real: there is no way to make a
webview app 200 KB. What you control is everything above the floor, and the
defaults already sit near it.

## What a release build gets

`voussoir build` passes these to cargo even when the app's `Cargo.toml` predates
them, and the scaffold writes them into its profile as well:

| Setting | Effect |
| --- | --- |
| `lto = true` | cross-crate inlining and dead-code removal; usually the largest single win and a small runtime improvement |
| `codegen-units = 1` | one unit means LTO sees everything, at the cost of a slower build |
| `strip = true` | debug symbols and the symbol table leave the binary; nothing reads them at runtime |

Android and iOS release builds get the same `--config` flags, because a `.so` or a
static library has the same problem.

`voussoir build --size` prints the result, so a change that grows the binary is
visible without reaching for `ls`.

## `opt-level`: `s` beats `z` here

Measured on the counter example, Linux x86_64, stripped:

| Profile | Bytes |
| --- | --- |
| `opt-level = "s"` (the default) | 2,533,088 |
| `opt-level = "z"` | 2,726,808 |

`z` optimizes for size first and in this dependency tree ends up larger, because
the webview crates hit slower broad-phase code. Leave the default `s`; measure
before changing it.

## Features are the real dial, not flags

Each feature is a dependency the binary may never use:

- `dialogs` pulls `rfd`, which carries the platform file-dialog code.
- `updater` pulls `ureq`, `rustls`, `base64` and `ed25519-dalek`; the TLS stack is
  the largest of these, and it has no smaller verified form.
- `rt` pulls tokio's multi-thread scheduler and timer wheel.
- `devtools` only changes what the webview exposes, but it is no longer part of
  `full`: `voussoir dev` turns it on, and a release does not carry it.

A notes app that never opens a native dialog can drop `dialogs` and `updater` and
keep `menu` and `storage`; the features are independent for exactly this reason.
What you cannot drop is `wry` on Linux: its `linux-body` feature is what delivers
POST bodies to the IPC handler.

## What runs per request

Static assets come from a table embedded at compile time, so serving one is a
lookup and a borrowed slice, not a file read. The generated table is sorted, and
the lookup binary-searches it (falling back to a scan for a table generated by an
older CLI, which keeps those apps correct). Events evaluate one script string for
every window that should receive it, so a broadcast is not re-serialized per
window.

## What not to do

- **Do not build release with `voussoir build --debug`.** That is the debug
  profile: no LTO, symbols kept, and a binary several times larger.
- **Do not enable `devtools` in `full` to get F12 once.** Run `voussoir dev`
  instead; it compiles devtools in for the dev shell.
- **Do not chase `panic = "abort"`.** The IPC layer catches panics so one broken
  command cannot take the window down; aborting would trade that for a few
  kilobytes.
